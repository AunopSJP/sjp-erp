# สัญญาบริการเป็นข้อมูลหลักของตัวเอง

ข้อเสนอนี้ตั้งอยู่บนสมมติฐานที่ยังไม่ได้ยืนยันกับแผนกที่เกี่ยวข้องหรือกับสัญญาจริง (ดู `docs/workflow-interview.md`): ถ้า SLA แยกตามสัญญาบริการ และสัญญาบริการไม่จำเป็นต้องผูกกับโครงการเดียว จะให้สัญญาบริการเป็นข้อมูลหลักแยกจากโครงการ มีลูกค้า ช่วงวันที่ ไซต์ที่ครอบคลุม และ SLA ของตัวเอง โดยโครงการ แผน PM และ Ticket อ้างถึงสัญญานั้น

## Considered Options

- เก็บไว้ในขั้น "บริการหลังส่งมอบ" ของโครงการตามเดิม: ง่ายกว่า แต่รองรับสัญญาที่ไม่ได้ผูกกับโครงการเดียวไม่ได้

## Consequences

- ยังไม่ได้ลงมือในโค้ด ต้องย้ายข้อมูลสัญญาที่อยู่ในโครงการและแผน PM และแก้รายงานกับ Dashboard ที่อ่านวันสิ้นสุดสัญญาจากโครงการ
